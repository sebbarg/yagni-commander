# Architecture

How yagni-commander is built, and why. What it does is in [SPEC.md](SPEC.md), what comes next in [ROADMAP.md](ROADMAP.md), how to build and run it in [README.md](README.md). Per-feature designs with their reasoning are in `docs/superpowers/specs/` and `docs/superpowers/plans/`.

## Goals

- Looks great and feels at home on macOS, Kubuntu (KDE Plasma) and Omarchy (Hyprland). Existing options fall short: Double Commander's macOS support is poor, Krusader lacks features.
- Keyboard-first, TC-style workflow with fully configurable keybindings.
- Fast (large directories, instant navigation) and secure (small attack surface, no `unsafe`).

## Decisions

- **GUI, not TUI.** Terminals intercept keys (Cmd shortcuts, Ctrl+Tab, etc.) inconsistently, so a TC keymap can't be guaranteed. A GUI also gives real multiple windows, drag and drop with Finder/Dolphin, and launching a configurable external editor (e.g. VS Code on F4).
- **gpui (Zed's UI framework), not iced.** Its action + context-scoped keymap system matches the TC model, `uniform_list` is virtualized with native smooth scrolling, text truncates with ellipsis, and redraw on resize is smooth. iced 0.14 was evaluated and rejected.
- **gpui comes via gpui-kit** (Longbridge, crates.io `gpui-kit = "0.7"`). gpui-kit pins `gpui-pre 0.3.7` (a snapshot of Zed commit `1a28cff`), re-exports gpui, provides `application()`, `init()` and `open_window()`, and includes gpui-component. Import everything through `gpui_kit::` (gpui APIs) and `gpui_kit::component::` (widgets); never add `gpui` directly, since two gpui crates in one build are incompatible types. The crates.io `gpui` itself (0.2.2, Oct 2025) is stale. Trade-off accepted: the snapshot is republished by a third party, not Zed, and the dependency tree is large (~700 crates). Its docs are thin: read the source under `~/.cargo/registry/src/*/gpui-component-0.7.0`, `gpui-base-0.7.0`, `gpui-pre-0.3.7`.
- **gpui-component** (via gpui-kit) provides inputs, dialogs, menus, the settings component and progress, which gpui lacks.
- **Themes are data.** A theme is a TOML file (`crates/yagni-commander/assets/themes/`) with `name`, `mode` (dark/light) and 21 colors named by role (`accent`, `selected`, `directory`, ...), never by hue. Every text color reaches WCAG AA (4.5:1) against each background it is drawn on, checked by `theme::tests::text_is_readable_on_its_backgrounds` (owner, 2026-10-04): `text_secondary` is for secondary text that is read (column details and titles, footers, status lines, hints, labels), `text_dim` only for what should recede (the inactive side's path header and tabs, placeholders). Every background role has a matching text role (`accent`/`text_on_accent`). gpui-component's theme is derived from these roles in code (`Theme::component_config`), including hover/pressed shades, so theme authors only define roles and we don't depend on gpui-component's theme format. Built-in themes (`tokyo-night`, `gruvbox-dark`, `classic`) are compiled in with `include_str!` and chosen by the `theme` config key; user theme files are v2 (see `ROADMAP.md`). The role `dialog_bg` is the background of every dialog: gpui-component's `Dialog` paints its own background and then applies the builder's style, so every `open_dialog` site goes through `themed_dialog` (`file_manager/commands.rs`), which sets `dialog_bg` last. In light mode gpui-component draws text fields on its `background`, which stays `panel_bg` (so Classic's fields are white like its lists).
- **Bundled monospace font, platform UI font.** The F3 viewer uses JetBrains Mono NL, bundled (about 200 KB), so it looks the same everywhere; without it gpui-component picks Menlo on macOS and DejaVu Sans Mono (or a stand-in) on Linux. NL, the variant without ligatures, so the viewer never draws `!=` as one sign. UI text keeps the platform's font to feel native (decided with the owner 2026-10-04); on Linux gpui guesses it from a fixed list (`gpui-pre` `text_system.rs`) rather than asking the desktop.
- **Errors are modal.** Errors show in a centered message box that stays until dismissed (`show_error` in `file_manager/commands.rs`); never toast notifications for errors.
- **Archive crates:** `zip` (zip2 project; default codecs off, Deflate via zlib-rs and Deflate64), `tar`, `flate2`, `bzip2`, `liblzma` (maintained fork of `xz2`), `zstd`. 7z and rar left out (immature / non-free). Chosen 2026-10-03 for stability; the owner accepted `.tar.xz` knowingly. `aes-crypto` on (AES zips from 7-Zip/WinRAR; adds RustCrypto `aes`, `hmac`, `pbkdf2`, `sha1`, `zeroize`). `hmac`, `pbkdf2` and `sha1` are also direct dependencies of core, at the versions zip uses, for `aes_authentic`.
- **Zoom like Zed:** the UI level through gpui-component's `font_size` and `Root`'s rem size; our sizes in rems; the viewer's level through `RemScope`. Two independent levels (UI, viewer), 10 to 32 px, kept in the state file. Spec `docs/superpowers/specs/2026-10-04-zoom-design.md`.
- **Same keymap on all platforms**, Ctrl not Cmd on macOS (only Quit differs: Cmd-Q / Alt-F4; macOS also takes Cmd-C for copy path, next to Ctrl-C). F-keys assume Fn is held on Mac keyboards.
- **Upstream bug, unreported by choice:** gpui-component `Dialog` binds Enter to OK for the whole dialog, ignoring the focused button (still on gpui-kit `main`; nearest related PR #3097). The owner decided not to file it for now; our `ButtonRow` works around it (see Gotchas).

## Code map

- `crates/yagni-commander-core`: UI-agnostic core, no gpui. Modules: `archive` (browsing into archives: `ArchiveIndex`, a tree of `Entry`s per folder built from `file_ops::extract`'s listing (`list_zip`, `read_tar_list`), with implied folders added and unsafe names left out; `Stamp` (size and time) decides whether a re-read can keep the index; `inner_parts`; `IN_ARCHIVE`, the refusal text. A panel inside an archive keeps `Option<Arc<ArchiveIndex>>`; its `path()` runs through the archive file (`/x/a.zip/src`), `real_dir()` is the archive's folder; `LoadRequest::archive` / `ArchiveRead` asks for an archive read, and a `Navigation` that carries the index is applied at once (`Panel::browse`)), `commander` (dual-panel state: `tabs: [Tabs; 2]`, each `Panel` with a session-unique `PanelId` (a copy's selection is cleared by id, `clear_selection`), `panel(side)` is the front tab, `tabs(side)` all of them; loads and quiet re-reads are found by id across every tab, so a background tab's read lands there and a closed tab's is dropped; a tab coming to the front re-reads quietly, or gets its first read with the startup fallback (`bring_to_front`); `start_tabs`/`StartTabs` read only the front tabs; `Command`s, rename/mkdir/quick-search entry points; a load state machine: navigation and reload commands queue a `LoadRequest` and keep the old listing, the UI takes them with `take_requests` and returns results through `finish_load`; ids drop stale results (Escape = `cancel_load`, newer navigation); commands for a loading panel are ignored, except that a click focuses it; a reload asked for while a read is pending marks the panel `stale` and runs once that read ends, cancelled or failed or not; that re-read is quiet; a quiet load (`watch_reload`, `Panel::refresh`, kept apart from `loading`) blocks nothing and shows nothing, takes the cursor entry when it finishes, and a quiet read of a vanished folder walks up to its nearest parent; other quiet-read errors are ignored), `tabs` (`Tabs`: a never-empty list of panels plus the front index; `label(path)`, the last component or `/`), `listing` (`read_listing`, with the startup fallback to the nearest readable parent, then home), `panel` (listing, cursor, sort, selection, `Summary`), `entry` (reading directories; `stat_entry` builds one entry, shared with the find walk), `sort`, `format` (size, time, permissions text), `fs_ops` (rename, no-replace rename, make directory, name validation), `file_ops` (copy/move/trash/delete engine `run`, background `Job`; delete walks with `openat`/`unlinkat` and `O_NOFOLLOW` so a directory swapped for a symlink mid-delete can't redirect it; `Pack`/`Extract` operations in child modules: `archive_names` (formats by extension, `stem`, entry-name checks `components`, `single_top_folder`), `safe_dir` (`SafeDir`: every extraction write through `openat` + `O_NOFOLLOW`, modes `& 0o777` minus the umask; `.`/`..` parts refused), `pack` (zip via the `zip` crate; each symlink asks through `Observer::link` / `Event::Link`), `extract` (zip and tar; tar read twice: names first for smart extraction and totals); `ExtractEntries` (F5/F3 inside an archive: a `Pick` in the extract `Sink` keeps the chosen entries under `inner`, renames the top one for `Destination::As`, no smart extraction), `compare` (`Operation::Compare`, run before the engine so nothing is logged; result in `Report::comparison`: `Comparison` with `Difference`s sorted by path; walks both trees without following symlinks, then reads same-size file pairs in 1 MiB chunks); `Conflict::incoming` describes an archive entry; encrypted zip entries ask through `Observer::password` / `Event::Password` (the engine remembers the password for the job; `Decrypted` turns data errors into "wrong password or a damaged entry"; `aes_authentic` checks the authentication code of deflated AE-2 entries before extracting, since zip checks it only when the encrypted data is read to its end and AE-2 has no CRC; `PasswordAnswer`'s `Debug` hides the password)), `terminal` (Ctrl-Shift-T: `choose(&Env, dir)` picks the default terminal and its folder argument from an injected `Env` (`$TERMINAL`, KDE and its `kdeglobals`, `PATH`); `open_terminal(command, dir)` starts it in `dir` without waiting, `command` replacing the detection (app tests set `FileManager::terminal`; v2's configured emulator can use it too)), `launch` (external editor; for Enter on a file, `is_program` (any execute bit and an ELF, Mach-O or `#!` start; the bit alone isn't enough on NTFS/FAT/SMB) and `run_program` (direct, no shell, in the file's folder, exit code ignored), else `open_with` runs the system opener without waiting, and reports a non-zero exit through a callback from its own thread; output is never piped, since an app the opener starts could hold the pipe), `oplog` (operation log: day files, startup pruning; the engine writes through `file_ops::Settings::log`, F2/F7/Shift-F4 through `Commander::set_log`), `quick_search` (the typed prefix), `viewer` (F3: `source` opens regular files only, with `O_NONBLOCK` so a FIFO can't block; `layout` turns a byte window into display rows; `document` caches 64 KiB blocks and navigates by byte position; `lines` counts lines in the background, keeping a count per MiB; `search`: `find(source, query, from, Direction, cancel, progress)`, the next match forward or the last one before `from` backward, in 1 MiB blocks cut at line ends, matches by `TextQuery::find_at` (the leftmost one-line match from a position, also behind Alt-F7's `is_match_in`); `Row::marks` / `Document::marked_rows` carry the current match into the layout (two ranges per hex row), `Row::mark_columns` the first one's columns; `hex`: `Wrap::Hex` rows (`hex_row`, `offset_digits`, `HEX_ROW`), with `Document` navigating hex by arithmetic, never reading the file to find a row start; selection: `Row::sources` (the file byte of each shown character) with `boundary_at`/`char_at`/`hex_column` (`HexColumn`) for hit tests, `Highlight` (the search mark and the selection, filling `Row::marks` and `Row::selection`), `Document::word_at`/`line_at`, `copy` (`Document::copy_text`, `Copy::{Text, Hex}`, `COPY_CAP`, `TooLarge`)), `config` (`save_setting` edits one key (a key only commented out in the template, such as `# theme = ...`, is added above that comment), `save_hotlist` replaces the `[[hotlist]]` tables; both with `toml_edit`, never writing a broken file), `find` (Alt-F7: `masks` (`Masks::parse`/`new(text, case_sensitive)`/`matches`/`enters`: `;`/space separated, `*`/`?`, case-insensitive unless the dialog's Case-sensitive is checked, implied `*text*`, excludes after `|`, `name/` folders not entered), `text` (`Text::compile` to a `TextQuery` over `regex::bytes`; `is_match_in` reads 1 MiB blocks cut at line ends, a match containing `\n` is skipped, `O_NONBLOCK` open, `Interrupted` on cancel), `walk` (`search(query, cancel, progress, found)`: hands each result as an `Entry` named by its relative path; depth first in name order, hidden included, symlinks not followed; a folder on another device is skipped only if it is a mount point in `/proc/self/mountinfo` (`other_filesystem`, `parse_mountinfo`; btrfs subvolumes are searched; without the table, as on macOS, the device decides); `Progress` (atomic counts; `so_far` for the status line and a stopped search), `SearchSummary`), `Results` ("Feed to panel": root, masks text, `Arc<Vec<Entry>>` shared with the dialog, named by relative path; `listing`, `recheck` re-stats and drops gone entries), `IN_RESULTS`. A results panel keeps `Option<Arc<Results>>` beside `archive`: `path()` is the root, so `path().join(name)` is the real path; a `Navigation` carrying results is applied at once; a reload (`LoadRequest::results`) re-checks; `watch_reload` skips it; `Commander::feed`, `Commander::go_to_file` (`Navigation::up_if_missing` / `LoadRequest::up_if_missing`: only a missing folder walks up to its nearest parent, an unreadable one is an error; leaving results uses it too); quick search and icons use a name's last component; rename/mkdir/new file refuse), `hotlist` (Ctrl-D entries: `label` turns `&` marks into the letter and an underline byte range, `find_letter`, `expand`/`contract` for `~`, `validate`, `default_name`; `Commander::go_to` navigates the active panel there, `Commander::home`), `info` (Properties: `read` (a symlink's kind, size and times are its target's), `from_entry` (inside an archive), `count` (iterative walk, links never followed, `cancel` flag), `lines` (all the box's text; `Count::{NotAFolder, Counting, Done}`); `ArchiveIndex::totals`/`entry` serve archives), `icons` (`icon(&Entry) -> char`: exact file name, lowercase name, extensions longest first, executable, generic; a hand-written special-folder list; the home folder's glyph comes from `Commander::icon(side, entry)`, which compares the panel path plus the name with home; symlinks never count as executable, since their own mode is always `rwxrwxrwx`; the table `icons/table.rs` is generated from nvim-web-devicons by `scripts/gen-icons.py`, rerun to update; `FONT_FAMILY`; tests check every glyph, the family name and the `m` mapping against the bundled font), `storage` (platform paths, TOML load/save, atomic writes), `watch` (directory watcher: `PanelWatcher`, one `std::thread` per watcher around a notify watcher, the only place notify's `watch` is called since it can hang on a dead mount (a call busy for `HUNG_AFTER` is abandoned: the next folder gets a new thread, the old one reports nothing); reports `Report::Changed(dir)` and `Report::Started(dir, modified)` naming the folder as given; paths canonicalized, compared ignoring case on macOS; a folder deleted or moved and recreated at the same path is watched again (inotify watches the inode); `is_relevant` drops access events so our own reads don't loop; `Throttle` 100 ms, then at most 1/s).
- `crates/yagni-commander`: the gpui app.
  - `Commander` lives in a gpui `Entity`, shared by the root `FileManager` view and two `PanelView` entities. Mutations go through `execute()` in `file_manager.rs`, which calls `cx.notify()`; views react via `observe`.
  - Keys map to gpui actions (`actions.rs`), actions map to core `Command`s or `FileManager` methods. The keymap is data, so a user config file can plug in there.
  - `file_manager/file_ops.rs`: F5/F6/F8 around a core `file_ops::Job`. A `spawn_in` timer polls the job every 50 ms; the progress dialog (a `ProgressView` entity inside a gpui-component `Dialog`) opens after 6 polls or on the first conflict; the conflict dialog stacks on top of it. `finish_job` closes the progress dialog, reloads both panels and shows failures (and links left out of a zip). Also Alt-F5 (`pack`, a confirm box before replacing a zip), Alt-F6/Alt-F9 (`extract`), and the symlink prompt (`ask_link`, opened on `Event::Link` like the conflict prompt, with a gpui-component `Checkbox` for "Same for the remaining links"), and the password prompt (`ask_password`, a masked `dialog_password_field`). Compare by content (`compare`; `compare_pair` picks the entries, `comparison_text` the result; `RunningJob::compare` keeps the pair for `finish_job`, which shows the result through `show_message_box` (wider, Ctrl-C copies every line) and skips the reload).
  - `file_manager/properties.rs` and `info_dialog.rs`: Alt-Enter's box (`RunningInfo`: details and the folder count arrive from a `std::thread` over a std channel polled every `OPENER_POLL`; the `id` keeps a closed box's late results out of the next one; `InfoView` draws label/value rows; Ctrl-C copies "Properties" plus `Label: value` lines).
  - `find_dialog.rs` and `file_manager/find.rs`: Alt-F7. `FindDialog` (kept in `FileManager::find` after closing, so fields and results survive) holds the four fields, the option checkboxes, the results (`uniform_list` in the `FindResults` key context: arrows, Enter = go to file, F3 = view), the status line (`status_text`), and the running search (a `std::thread` sending `Found`s over a std channel, polled every `OPENER_POLL`; `id` drops a stopped search's late results). "Skip folders" (`skip_control`): a focusable control under Search in and a popup (`deferred(anchored)` at `POPUP_PRIORITY`, `FindSkip` key context) of `find::SKIP_FOLDERS`, defaults `find::DEFAULT_SKIP`, saved in the state file as `find_skip`; `Query::skip` folders are neither listed nor entered, counted in `SearchSummary::skipped`. Alt-L (`find_results::Feed`, `FindDialog` key context on both the view and the footer wrapper, since the buttons are outside the view) feeds to the panel. It emits `FindEvent`s (`GoTo`, `View`, `Feed`, `Closed`) that `FileManager::on_find` acts on. The dialog's `on_ok` (Enter in a field) searches and stays open; `on_cancel` (Escape) stops a running search first. Tests hold a search before its walk with `FindDialog::hold`. The option boxes are our own (`option_box`, Space in the `FindOption` context): gpui-component's `Checkbox` draws its focus ring at a fixed faint opacity and keeps its focus handle private. The list's cursor is bright only while the list has focus (else `cursor_inactive_bg`), its border turns accent. Resizable from a grip in the footer's corner (`find_dialog::grip`, dots drawn from 2 px squares so it sits at the same inset from both edges; a glyph lands wherever its font puts it): `grown` adds to `MIN_WIDTH` and the list height, never below the opening size, kept for the session; the dialog builder reads `width()` on every render, and a `canvas` registers window-wide mouse listeners so the drag follows the mouse outside the dialog.
  - `button_row.rs`: the button row used by every dialog (see Gotchas). `set_label` and `set_enabled` (a disabled button is drawn so and ignores presses); each button sits in a div with `debug_selector` `button-<label>` for tests. While the row has focus its selected button gets `focus_ring` (an accent band, `focus-ring-<what>`; also used by the find dialog's option boxes); the selected button's primary look alone marks the default for Enter in a text field. `set_copy_text` makes Ctrl-C / Ctrl-Ins (Cmd-C on macOS; `CopyText` in the `ButtonRow` context) copy that text; `show_message` sets it to the title and text. Without it the keys pass on.
  - `menus.rs`: the menus as data (`MenuDef`, `MenuEntry`), built by `menus(MenuState, mac)`; `to_gpui` feeds `cx.set_menus` (native on macOS), `popup` builds a gpui-component `PopupMenu` (the Linux bar now; a right-click menu in v3). Items dispatch the same actions as the keys, to `FileManager`'s focus. `FileManager::update_menus` (from its `Commander` observer) rebuilds them when the check marks (hidden files, the active panel's sort column) change.
  - `hotlist_popup.rs`: the Ctrl-D popup (`HotlistPopup`, our own view: gpui-component's `PopupMenu` has no letter keys). Emits `HotlistEvent`s that `FileManager::on_hotlist` acts on; drawn by `FileManager` right under the active panel's tabs (`panel_view::BELOW_TABS`). While it is open, `FileManager`'s keystroke interceptor lets only `hotlist_popup::passes` keys through, and the popup's `on_key_down` stops letters from reaching the quick search.
  - `hotlist_dialog.rs`: Configure (`HotlistDialog`, OK/Cancel, its list in the `HotlistList` key context). Edits a copy of the list; OK validates every path, then `FileManager::save_hotlist` (also used by "Add current folder") saves with `config::save_hotlist` and `apply_config`. `FileManager::config_refused` refuses both while `CurrentConfig.problem` is set.
  - `menu_bar.rs`: the Linux in-window bar (`MenuBar`). Not gpui-component's `AppMenuBar`: that one can't be opened from the keyboard (private methods). F10 (`ToggleMenu`) and a lone Alt (`MenuAlt`) open it, Alt-F (`OpenFilesMenu`) opens Files (`menu_bar::passes` lets it through while a menu is open); Left/Right arrive as gpui-base's `SelectLeft`/`SelectRight` propagated from the popup.
  - `file_manager/loads.rs`: runs the commander's directory reads, one `std::thread` per read (never gpui's background pool: a dead NFS read would hold a pool thread forever), polled every 10 ms for a read's first 150 ms, then every 100 ms; after 150 ms the panel header shows "Loading <path>... N entries" and the old listing dims; it redraws only when the count changed, so a hung read stays quiet. A quiet request (`LoadRequest::quiet`) of a folder whose last quiet read took `SLOW_READ` or more waits as long again (`rest`, `FileManager::quiet_reads`). The `FileManager` observer of the `Commander` starts new reads; dialogs and file operations check `active_loading` first (F5/F6 also wait for the other panel, their destination).
  - `file_manager/watch.rs`: spawns two `PanelWatcher`s (not tied to sides), points them at the loaded front tabs' folders from the `Commander` observer (`watched`, `watch_panels`: a watcher already on a needed folder keeps it), and turns their reports (a `futures` unbounded channel awaited by one `spawn_in` task, no polling) into `Commander::watch_changed` / `watch_started`, which re-read each side showing that folder. Ctrl-R clears `watched` so both are watched again.
  - `viewer_view.rs`: the F3 viewer window (`ViewerView`, its own `Viewer` key context and `actions::viewer` actions, byte-based scrollbar; F4 (`edit`) runs the editor through `commands::configured_editor` and core `launch::open_in_editor`, refused when the viewer holds an archive entry's `temp` copy; `wrap` and `hex` pick the core `Wrap`, `wraps_rows` says whether rows are cut to the window or scrolled sideways, `relayout` keeps the top byte on a mode change). `viewer_view/search.rs`: Ctrl-F/F3/Shift-F3 (`FindView` dialog body, `LastSearch` global, `SearchState`: the window's query, current match and running search on a `std::thread` with a cloned `FileSource`, polled every `OPENER_POLL`; `reveal`; tests hold a search with `search.hold`). `viewer_view::open` takes Alt-F7's `Text` (`FindEvent::View(path, Option<Text>)`, from `FindDialog::searched`, the text of the search that found the results). `viewer_view/select.rs`: the selection (`Selection`: a byte range with the hex column a drag started in), hit tests against the rows last drawn (`drawn`, `text_area`; the mouse down handler sits on the rows' div, so scrollbar clicks never reach it), auto-scroll on a 50 ms `spawn_in` timer (`TICK`), `highlight_runs` (mark over selection over dim, one cursor per range list so it stays linear), Ctrl-A (`SelectAll`) and Ctrl-C/Ctrl-Ins (`viewer::Copy`); `search.rs` sets the selection to a found match and prefills Ctrl-F from it (`find_prefill`). `option_box.rs`: the option box shared by the find dialog and the viewer's Find dialog. Rows are laid out around the top byte position on every render; nothing depends on the file size. Giant lines get forced row breaks at 64 KiB-aligned offsets (when the 64 KiB before has no `\n`), so scrolling up never scans far back.
  - `zoom.rs` and `rem_scope.rs`: `Zoom { ui, viewer }` is a gpui global (`DEFAULT`/`MIN`/`MAX` 16/10/32, `clamp`, `step`); `rems_from_px` (px / 16), `scaled(px, level)` (arithmetic on sizes at the level in use), `dialog_width(px, cx)` (px at the UI level, for builders that take only `Pixels`, such as `Dialog::w` and the find list height); `apply_ui` sets gpui-component's theme `font_size` and refreshes the windows (`Root` turns it into the rem size on every frame); `change_ui`/`reset_ui`, `change_viewer`/`reset_viewer`. `RemScope` is an element that runs layout, prepaint and paint in `window.with_rem_size`; `ViewerView` wraps its content in it at `Zoom.viewer`. The viewer's text is a fixed 13 px base (`MONO_SIZE`) scaled by the viewer level. Actions `ZoomIn/ZoomOut/ZoomReset` in the `FileManager` context and `viewer::ZoomIn/...` in `Viewer`; the Show menu has the items. State keys `ui_zoom`, `viewer_zoom` (f32, clamped on load).
  - `windows.rs`: closing the main window closes every viewer and quits. `APP_ID` ("yagni-commander") is set on every window: Wayland `app_id`, X11 `WM_CLASS` (checked by the smoke script with `xprop`). gpui sets no window icon on Wayland or macOS; icons come with packaging (`.desktop` file plus icon theme, `.app` bundle).
  - `config_state.rs`: the `CurrentConfig` global: the settings in use, the file's path, and `problem` (why the file is not in use: parse error or no config directory; while set, the settings dialog is disabled and nothing is saved). `FileManager::change_setting` (dialog) saves one key with core `config::save_setting` (`toml_edit`: comments, layout and hand edits survive; a broken file is never written) and then `apply_config` (sort, log, installs the theme, sets the unknown-theme notice, makes it the global). Ctrl-R calls `reload_config`, which applies a good file or keeps the settings and shows "Config ignored: ...".
  - `settings_dialog.rs`: the Settings dialog (`SettingsView`: a Theme dropdown (gpui-component `Select`, `settings-theme`) first, two `text_field`s and two gpui-component `Switch`es, plus a `ButtonRow` with Close). A text field is saved only if typed into (so its opening text can't undo a hand edit of the file), on blur and on every way out; Enter and Close stay in the dialog while the days value is invalid, Escape drops it. Save errors show after the dialog has closed (`window.defer`), since closing pops the top dialog.
  - `file_manager/commands.rs`: F2/F7/Shift-F4 name prompt (`prompt_name`, a gpui-component `Dialog` with an `Input`), F4 and Shift-F4 editor launch, quick search key handling, `show_error` / `show_message`, About.
  - The active `Theme` is a gpui `Global` (`theme.rs`: `BUILTIN` (id, file text), `Theme::builtin`, `Theme::named` (theme or Tokyo Night, plus whether the id was unknown), `ids_and_names`, `switch_theme` (install, then `refresh_windows`)); `Theme::install` also applies it to gpui-component. Built-in default: Tokyo Night (Omarchy's default).
  - Views take every color from `Theme::get(cx).colors`. `clippy.toml` bans gpui's color constructors (`rgb`, `hsla`, `black`, ...) so literals can't creep in; add a new role to `Colors` and every theme file instead.
  - The loaded `Config` is a gpui global, `CurrentConfig` (`main.rs`).
  - The window is opened with `gpui_kit::open_window`, which wraps `FileManager` in gpui-kit's `Root` (needed for dialogs).
  - State file: `app_state.rs` keeps an `AppState` global (window geometry, updated via `observe_window_bounds`; each side's tab folders and front index (`left_tabs`, `left_tab`, ...; an old file's `left`/`right` are read once, never written; command-line folders replace the front tab's folder) and the active side, updated by `FileManager`'s observer of the `Commander`; `show_hidden`; the last viewer geometry) and saves it on quit. It is loaded before the window opens, since `Commander::start` needs `show_hidden` and the folders (`State::startup_dirs`: arguments, else saved folders, else home; nothing is read there, the background read falls back). Window restore falls back to centered if the geometry no longer overlaps a display.
  - Hidden entries: `Panel` keeps them in a separate unsorted list while hidden, so `entries()` and every index (cursor, quick search, summary, selection) only see visible ones.
  - Column layout and cell text live in `columns.rs` (`visible_columns(commander, width, ui)`: the configured columns that fit, optional ones dropped from the right until Name keeps `NAME_MIN_WIDTH`; the width comes from `file_manager::panel_width` (window width, padding, divider, `split_ratio`, which `FileManager` copies into each `PanelView::split` on a drag), computed during render, so there is no frame of lag and no reading of last frame's bounds; `Column::tabular_figures`: Size and Modified turn on the font's `tnum` feature, since macOS's system font has proportional digits); panel rendering in `panel_view.rs` (the tab header, `tab-<side>-<ix>`: 160 px tabs that shrink evenly, the front one in the path header's colors (background and text: bright on the active side, dim on the other), the first one flush with the panel's square top-left corner; tabs and panels use the quiet `border` color on both sides (no accent border since 2026-10-02): the active side shows by its brighter path header, front tab and cursor bar, and while icons are on by an accent open-folder glyph before the path (`pwd-<side>`, `icons::CURRENT_FOLDER`; dim on the inactive side); the icon slot, `icon-<side>-<ix>`, shown while `Commander::shows_icons`).
  - `fonts.rs` registers the bundled fonts at startup: the icon font (`assets/fonts/`, Symbols Nerd Font Mono from Nerd Fonts v3.5.1, patched by `scripts/patch-icon-font.py`; see Gotchas); and JetBrains Mono NL v2.304 (`fonts::MONO_FAMILY`, OFL 1.1, from the release zip unchanged), which `Theme::component_config` sets as gpui-component's `mono_font_family`, so the F3 viewer uses it. UI text stays the platform font.
- Settings: `Config` is a hand-editable TOML file, created from a commented template on first start, edited by the Settings dialog one key at a time. A file that fails to parse is never overwritten; the app shows the error in the status line and runs on defaults (at startup) or keeps its settings (Ctrl-R).
  - Config: `~/.config/yagni-commander/config.toml` (Linux), `~/Library/Application Support/yagni-commander/config.toml` (macOS). Keys: `theme`, `editor`, `case_sensitive_sort`, `log`, `log_keep_days`, `show_modified`, `show_owner`, `show_permissions`, `icons`, `hotlist` (`[[hotlist]]` tables: `name`, `path`).
  - State: `~/.local/state/yagni-commander/state.toml` (Linux), same folder as config on macOS.
  - Operation log (when `log = true`): `logs/operations-YYYY-MM-DD.log` next to the state file (see `SPEC.md`, Operation log).
- `packaging/icons/`: the app icon, not compiled into the binary (no packaging exists yet). Everything in it is written by `scripts/gen-app-icon.py` (needs shapely and cairosvg; edit the script and rerun, never hand-edit the outputs). Drawn from scratch by construction (a rounded square cut by two diagonal gaps, a black rounded tile in a gap ring, "yc" as blocky 8-bit pixel letters from a character grid, `GLYPHS`), plain filled paths only, so the project owns it (MIT). Replaced a Recraft AI icon made on the free plan (Recraft owns those; not distributable). The files:
  - Installed: `yagni-commander.svg` (Linux `hicolor/scalable/apps`; the art fills the canvas, transparent background) and `hicolor/<n>x<n>/apps/yagni-commander.png` (16 to 512, copied as is into the icon theme).
  - Input of `iconutil -c icns` (on a Mac) for the `.app` bundle: `yagni-commander.iconset/` (16 to 1024 px, rendered from the macOS art; up to 32 px with the small "y").
  - Sources of the PNGs only, not installed: `yagni-commander-small.svg` (the 16 to 24 px PNGs: a 4×6 pixel "y", `SMALL_GLYPHS`, one pixel per screen pixel at 16 px) and `yagni-commander-macos.svg` (the art at 82% on a black 824 px rounded square with Apple's 100 px margin; circular corners, not Apple's squircle, no shadow).
- `unsafe_code` is forbidden workspace-wide.
- More pointers: `Panel::targets()` (selection, else the cursor entry, never "..") is what file operations act on; the quick search state lives in `Commander` (`search_*`), so every command ends it; `Commander::hide_columns` and `columns::visible_columns` (optional columns); `file_ops::Destination::{Into, As}` (F5/F6 into a folder or to a full path); `Commander::check_dir` (F2/F7/Shift-F4 refuse when the panel moved because its folder vanished); `Listing::modified` and `Commander::watch_started` (changes made during a read); `LoadRequest::cancel` (stops an archive read); `Panel::error` (a background tab's failed read, shown when it comes to the front); `Results::text` (F3 on a text-search result opens at the match); `launch::SYSTEM_OPENER`; `actions::quits` (Quit while a popup is open); `menu_bar::Opened` (a menu opened with the mouse ends the quick search); `select::follow_drag` (window-wide listeners for the viewer's drag); text-field keys (Ctrl-Ins, Shift-Del, Shift-Ins) are bound in gpui-base's `Input` context in `actions.rs`; sorting is also available as `SortBy*` actions, unbound by default.

## Known issues

- Below about 210 px (Name at its 120 px minimum plus Size), Name shrinks anyway: only optional columns are dropped for it.
- The owner reported that only Name sorting seemed to work on their machine; Size and Modified sort correctly in headless tests. Unverified. Note that owner/permissions sorts look like name sorts in directories where those values are all equal.
- Reading a big folder takes ~320 ms per 100k entries on Linux (~70% of it one `stat` per entry), near-instant on macOS. It runs in the background now; making the `stat` cheaper would only shorten the wait.
- A folder given on the command line is checked synchronously before the window opens, so one on a dead mount still hangs startup (accepted: the user typed it).
- No-replace rename (F2, move) is atomic only on Linux glibc (`renameat2`). On macOS it checks, then renames, so another process could create the target in between (TOCTOU); fixing it needs `renamex_np`, which nix doesn't offer without our own `unsafe`.
- A config problem shows in the status line and clears on the next keyboard command, not on mouse clicks.
- `PanelView::visible_rows` reads gpui scroll-handle internals (public fields); likely to break on a gpui upgrade.
- gpui cannot write file paths to the clipboard (copy in app, paste in Finder/Dolphin), and drag-out to other apps works on macOS and Wayland only (not X11). Both need platform code or another crate.

## Gotchas

- gpui animations run on wall-clock time (`Instant::now`), not the test clock. gpui-component's `Dialog` slides in for 250 ms, so a test that reads a control's bounds and then clicks could miss under a loaded parallel run (the settings tests failed about 1 in 25 to 60). The test `setup` turns on `cx.set_reduce_motion(true)`, which settles animations on their first frame; `dialogs_appear_in_place_so_clicks_land` guards it.
- App tests read folders inline (`open` sets `FileManager::load = None`), so keys take effect at once. To keep a panel loading, `use_held_loads` plus a `hold` file in the folder being read; drive it with `wait_until`. Core tests finish reads with `run_loads_now` (or the `run` helper).
- App tests have no real watchers (`FileManager::new` starts none under `cfg(test)`: a report from a watcher thread would panic gpui's test scheduler); report a change with `changed(cx, side)` or any `watch::Report` with `report(cx, ...)`. Core watcher tests use real time and notify; `watch_and_wait` returns once the watch is in place.
- Tests must never call the real `trash::delete` (it would fill the owner's trash): core `file_ops` tests pass `file_ops::Settings { trash: fake_trash, .. }` to `run` / `Job::spawn`, and app tests set `FileManager::trash` to a fake (`use_fake_trash`). Only `scripts/smoke.sh` uses the real trash, with `XDG_DATA_HOME` in a temporary folder.
- A panel's `path()` can run through an archive file (`/x/a.zip/src`): use `real_dir()` for anything on disk (watcher, state file, hotlist). Writing commands call `FileManager::refuse_in_archive`; core `rename`/`make_directory`/`create_file` refuse too, and a stray `path().join(name)` inside an archive can't exist, so it fails instead of touching the real folder. F3 inside an archive runs a `Kind::View` job (not logged); the viewer window owns the `tempfile::TempDir`, under `viewer-tmp/<pid>` (`storage::clear_stale_temp` at startup removes folders of instances no longer running; app tests set `FileManager::temp_dir`, `None` by default).
- Sizes in views go through `zoom::rems_from_px`, never `px(...)` (except 1 px borders, the window snap margins and the window size and geometry, which stay px on purpose); arithmetic on sizes uses `zoom::scaled` with the level in use.
- Ctrl-Shift-T in tests: `window_on` sets `FileManager::terminal` to `true`, so no real terminal starts; `mod open_terminal` uses `sh -c 'pwd > out'`. The smoke script exports `TERMINAL` as a recording script, which goes through the real detection.
- Enter on a file: `FileManager::open_file` decides and starts on a `std::thread` (reading the file's header could hang on a dead mount). `FileManager::opener` is the program run for non-programs (`xdg-open`/`open`); app tests set it to `true` in `window_on` so no real app ever starts, and `mod open_file` tests use a recording script. A failure comes back over a std channel polled every 100 ms (`OPENER_POLL`): a futures wake-up from the opener's thread panics gpui's test scheduler ("not deterministic"). Tests that exec a freshly written script first run it until it no longer fails with ETXTBSY (another test's fork can briefly hold it open for writing). The smoke script puts a recording `xdg-open` first on `PATH` and runs an executable `run.sh`.
- App tests of F5/F6 run a real worker thread: drive them with `advance_clock` + `run_until_parked` in a loop (`wait_until` in `file_manager/tests.rs`); the poll timer only fires on the test clock.
- gpui-component `Dialog` maps Enter to its OK action (`on_ok`) for the whole dialog, even when a text input or another button has focus (upstream bug, not reported as of 2026-09-30), and has no arrow-key navigation. So every dialog's buttons are our `ButtonRow` (`button_row.rs`), never `DialogFooter`/`DialogAction`/`open_alert_dialog`: it keeps its own selected button and binds Left/Right, Tab/Shift-Tab, Enter and Space in its own key context. Focus the row when a dialog opens (`focus_when_open`), except prompts, which focus their text field (Enter there still goes to `on_ok`; don't also handle the input's `PressEnter`, or OK runs twice: `enter_submits_a_prompt_exactly_once`).
- A gpui-component `Dialog` body (`.child`) clips its children and has no vertical padding, and the focus ring is drawn 3 px outside a control. A text field at the top or bottom of a body goes through `dialog_field` (`file_manager/commands.rs`), which adds the room; otherwise the ring is cut off top and bottom.
- gpui's Linux text system drops any font without a glyph for `m` (gpui-pre-wgpu `cosmic_text_system.rs`, `load_family`), silently, so text falls back to the UI font and shows hex boxes. The bundled symbols font is patched to map `m` to an empty glyph (`scripts/patch-icon-font.py`, needs fontTools); the core test `the_font_maps_m_so_gpui_keeps_it` guards it. App tests use a no-op text system, so only a screenshot shows whether glyphs render.
- gpui panics on the first line it lays out in a font family it can't find. gpui-component swaps its own default monospace family for an installed one, but a family we name (`fonts::MONO_FAMILY`) is used as is, so the bundled font must register: `fonts` tests parse the file and check its family name and its `m`.
- A popup drawn inside a dialog (`deferred(anchored(...))`) needs `.with_priority(gpui_kit::base::POPUP_PRIORITY)`: the dialog layer itself is deferred with priority 10 and up, so a lower one paints underneath it and is invisible. App tests can't see this (the popup is laid out and even takes clicks there); only a screenshot does (`08i1-find-skip-popup` in the smoke run).
- Opening a dialog moves focus to it: focus a field inside it with `window.defer` after opening. After an error box closes, focus must be put back explicitly (`show_error`'s `refocus`).
- An event handler running inside an entity's update must not update that same entity again (panics "already being updated"); defer with `window.defer`.
- Tests of the settings dialog: point `CurrentConfig.path` (helper `use_config`) and `FileManager::log_dir` (`use_log_dir`) at temporary folders, never the real ones. Call `activate(cx)` first (blur events need an active window), and use `press(cx, key)` for Space/Enter on a switch or button (gpui clicks on key-up; `simulate_keystrokes` sends only key-down).
- Text fields: use `commands::text_field`, never a bare `Input::new`. gpui-component's default input (32 px, 8 px vertical padding) leaves 14 px for a 20 px line and cuts off descenders; `text_field` sets 5 px.
- `ThemeConfigColors` (gpui-component) has private fields: build it from `default()` and assign fields, not with struct-update syntax.
- Viewer windows in app tests: find them with `viewer_view::tests::viewer_in` over `cx.windows()` and drive them with `VisualTestContext::from_window`. In the smoke script (no window manager) the new viewer window must be focused with `xdotool windowfocus`.
- Menu shortcut labels: gpui-component's menus (Linux) show an action's last-registered binding, the native macOS menu its first (gpui-pre-macos `platform.rs`). So a primary key is registered both before and after its alternative (F8, Del, F8). Quit has one binding per platform for the same reason. Pinned by `menu_labels_show_the_primary_keys`.
- gpui dispatches key bindings before `on_key_down` listeners. The hotlist popup's `on_key_down` stops letters from reaching the quick search, but a file-manager binding on a bare (or Shift) character would still fire while the popup is open, since `hotlist_popup::passes` lets single characters through. Keep such bindings out of the `FileManager` context, or extend `passes`.
- Lone Alt is gpui's modifier-only binding `"alt"` (fires on release if no key came in between). gpui doesn't count mouse clicks or window switches, so `FileManager::alt_armed` is cleared by those. A keystroke interceptor (`intercept_keystrokes` in `FileManager::new`) swallows every key but the menu's own while a menu is open, because the panel bindings are on the open popup's dispatch path. gpui test windows start inactive, and gpui reports focus changes (`on_focus_out`) only for the active window: call `window.activate_window()` first in such tests. An open menu closes when focus leaves its popup (e.g. a dialog opens). Lone-Alt tests that follow an activation advance the test clock past `ALT_AFTER_ACTIVATION`. The menu-bar app tests are in `mod menu_bar` in `file_manager/tests.rs`, compiled on Linux only.
- Open dialogs through `themed_dialog`, or they paint gpui-component's background instead of `dialog_bg`.
- gpui-base's `Select` propagates Enter, and the `Dialog` binds Enter to OK, so Enter on a closed `Select` would close the dialog and Space does nothing. Our `select::Open` action (`actions.rs`, `Select` key context) opens it; the owner of the `Select` (the settings wrapper) handles it without propagating. A new `Select` in a dialog needs the same wrapper. A searchable `Select` would have Space pick inside its search field.
- Icons (e.g. menu check marks) need gpui-kit's assets: `main.rs` registers `gpui_kit::assets::Assets`; without it icons render blank.
- Alt-F4 is bound to Quit (Linux); the `Viewer` context rebinds it to close only that viewer.
- Archive tests build malicious archives on purpose: `zip::ZipWriter::start_file` accepts any name; tar names and link names go in raw through `header.as_old_mut()` (`set_path` refuses `..`). `ZipFile::unix_mode()` includes the file-type bits. `tar::Header::mode()` fails on headers without a mode.
- Encrypted zip tests: ZipCrypto and AES headers start with random bytes, so a wrong password passes the quick check by chance (ZipCrypto 1 in 256). Tests that need a wrong password rejected rewrite the zip until it is (`make_locked_zip`'s `rejects`).
- macOS (unverified): apps started from Finder get a minimal `PATH`, so an `editor` like `code` may not be found; use a full path in the config if so.

## Testing

- `cargo test --workspace` and `cargo clippy --workspace --all-targets` (must be warning-free).
- `cargo llvm-cov --workspace --summary-only`: coverage. Core is kept near 100%; the uncovered lines need root or a file owned by an unknown uid.
- App tests live in `file_manager/tests.rs`. Mouse tests find elements by `debug_selector` (`row-left-3`, `tab-left-0`, `header-right-Size`, `divider`, `search-left`) and `cx.debug_bounds`; a missing selector also means the element was not drawn. Jobs that must stay running use `use_fake_trash` plus a `hold` file.
- App tests use gpui's `TestAppContext` (`#[gpui_kit::test]`) and build the window like the app does (`gpui_kit::init` + `Root`), so dialogs work. Drive them with `simulate_keystrokes` / `simulate_input` and `run_until_parked`; check dialogs with `window.has_active_dialog(cx)`. gpui's test window does not expose the title, so title text lives in a pure function.
- `scripts/smoke.sh [screenshot-dir]`: runs the real debug build under Xvfb through the main features (Enter on a file via a fake `xdg-open`, quick search, Ctrl-C/Ctrl-Ins path copy checked with xclip, F7, Shift-F4, F2, F5 with a conflict, F6, F8 into a temporary trash, Shift-Del, Ctrl-., Ctrl-D (add the folder to the hotlist, jump back by its letter, checked by window title), the Owner column switch (hidden through the restart), Files > Compare by content on two folders through F10 (checked with xclip), Alt-F7 (a name search with an exclude fed to the panel and copied out with F5, a content search with go to file checked by window title), F3 on a 200,000-line file (a mouse drag copied with Ctrl-C, checked with xclip) and a 300 KB single line, a file created and a folder deleted outside the app (watcher), tabs (Ctrl-T, Ctrl-Tab, Ctrl-Shift-Tab, Ctrl-W, a background tab catching up), quit, restart without arguments onto the saved tabs), then the theme block (Settings > Theme dropdown picks Classic with the keyboard, checked by screenshots and `theme = "classic"` in the config; switched to Gruvbox Dark with the dropdown, checked by `theme = "gruvbox-dark"` in the config; theme kept through the restart), a narrow window (`07n`, optional columns dropped for Name), then the zoom block (150% in the main window, a prompt, the Show menu and a viewer (`12a` to `12d`), with the `ui_zoom` and `viewer_zoom` state-file checks). - `scripts/make-test-files.sh [count] [dir]`: create a large directory under `/tmp` for stress tests.
