# yagni-commander

A personal, cross-platform dual-pane file manager in the spirit of Total Commander (TC), written in Rust with gpui. It implements the ~20% of TC the owner actually uses, not a full clone.

**Requirements live in `Requirements.md`** (the working document: v1/v2 scope, keymap, product decisions, build order). Read it before planning features and keep it updated when decisions change.

## Goals

- Looks great and feels at home on macOS, Kubuntu (KDE Plasma) and Omarchy (Hyprland). Existing options fall short: Double Commander's macOS support is poor, Krusader lacks features.
- Keyboard-first, TC-style workflow with fully configurable keybindings.
- Fast (large directories, instant navigation) and secure (small attack surface, no `unsafe`).

## Decisions

- **GUI, not TUI.** Terminals intercept keys (Cmd shortcuts, Ctrl+Tab, etc.) inconsistently, so a TC keymap can't be guaranteed. A GUI also gives real multiple windows, drag and drop with Finder/Dolphin, and launching a configurable external editor (e.g. VS Code on F4).
- **gpui (Zed's UI framework), not iced.** Its action + context-scoped keymap system matches the TC model, `uniform_list` is virtualized with native smooth scrolling, text truncates with ellipsis, and redraw on resize is smooth. iced 0.14 was evaluated and rejected.
- **gpui comes via gpui-kit** (Longbridge, crates.io `gpui-kit = "0.7"`). gpui-kit pins `gpui-pre 0.3.7` (a snapshot of Zed commit `1a28cff`), re-exports gpui, provides `application()`, `init()` and `open_window()`, and includes gpui-component. Import everything through `gpui_kit::` (gpui APIs) and `gpui_kit::component::` (widgets); never add `gpui` directly, since two gpui crates in one build are incompatible types. The crates.io `gpui` itself (0.2.2, Oct 2025) is stale. Trade-off accepted: the snapshot is republished by a third party, not Zed, and the dependency tree is large (~700 crates). Its docs are thin: read the source under `~/.cargo/registry/src/*/gpui-component-0.7.0`, `gpui-base-0.7.0`, `gpui-pre-0.3.7`.
- **gpui-component** (via gpui-kit) provides inputs, dialogs, menus, the settings component and progress, which gpui lacks.
- **Themes are data.** A theme is a TOML file (`crates/yagni-commander/assets/themes/`) with `name`, `mode` (dark/light) and ~19 colors named by role (`accent`, `selected`, `directory`, ...), never by hue. Every background role has a matching text role (`accent`/`text_on_accent`). gpui-component's theme is derived from these roles in code (`Theme::component_config`), including hover/pressed shades, so theme authors only define roles and we don't depend on gpui-component's theme format. Theme selection and user theme files are v2 (see `Requirements.md`).
- **Errors are modal.** Errors show in a centered message box that stays until dismissed (`show_error` in `file_manager/commands.rs`); never toast notifications for errors.
- **Archive crates:** `zip` (zip2 project; default codecs off, Deflate via zlib-rs and Deflate64), `tar`, `flate2`, `bzip2`, `liblzma` (maintained fork of `xz2`), `zstd`. 7z and rar left out (immature / non-free). Chosen 2026-10-03 for stability; the owner accepted `.tar.xz` knowingly. `aes-crypto` on (AES zips from 7-Zip/WinRAR; adds RustCrypto `aes`, `hmac`, `pbkdf2`, `sha1`, `zeroize`). `hmac`, `pbkdf2` and `sha1` are also direct dependencies of core, at the versions zip uses, for `aes_authentic`.
- **Same keymap on all platforms**, Ctrl not Cmd on macOS (only Quit differs: Cmd-Q / Alt-F4; macOS also takes Cmd-C for copy path, next to Ctrl-C). F-keys assume Fn is held on Mac keyboards.

## Architecture

- `crates/yagni-commander-core`: UI-agnostic core, no gpui. Modules: `archive` (browsing into archives: `ArchiveIndex`, a tree of `Entry`s per folder built from `file_ops::extract`'s listing (`list_zip`, `read_tar_list`), with implied folders added and unsafe names left out; `Stamp` (size and time) decides whether a re-read can keep the index; `inner_parts`; `IN_ARCHIVE`, the refusal text. A panel inside an archive keeps `Option<Arc<ArchiveIndex>>`; its `path()` runs through the archive file (`/x/a.zip/src`), `real_dir()` is the archive's folder; `LoadRequest::archive` / `ArchiveRead` asks for an archive read, and a `Navigation` that carries the index is applied at once (`Panel::browse`)), `commander` (dual-panel state: `tabs: [Tabs; 2]`, each `Panel` with a session-unique `PanelId` (a copy's selection is cleared by id, `clear_selection`), `panel(side)` is the front tab, `tabs(side)` all of them; loads and quiet re-reads are found by id across every tab, so a background tab's read lands there and a closed tab's is dropped; a tab coming to the front re-reads quietly, or gets its first read with the startup fallback (`bring_to_front`); `start_tabs`/`StartTabs` read only the front tabs; `Command`s, rename/mkdir/quick-search entry points; a load state machine: navigation and reload commands queue a `LoadRequest` and keep the old listing, the UI takes them with `take_requests` and returns results through `finish_load`; ids drop stale results (Escape = `cancel_load`, newer navigation); commands for a loading panel are ignored, except that a click focuses it; a reload asked for while a read is pending marks the panel `stale` and runs once that read ends, cancelled or failed or not; that re-read is quiet; a quiet load (`watch_reload`, `Panel::refresh`, kept apart from `loading`) blocks nothing and shows nothing, takes the cursor entry when it finishes, and a quiet read of a vanished folder walks up to its nearest parent; other quiet-read errors are ignored), `tabs` (`Tabs`: a never-empty list of panels plus the front index; `label(path)`, the last component or `/`), `listing` (`read_listing`, with the startup fallback to the nearest readable parent, then home), `panel` (listing, cursor, sort, selection, `Summary`), `entry` (reading directories; `stat_entry` builds one entry, shared with the find walk), `sort`, `format` (size, time, permissions text), `fs_ops` (rename, no-replace rename, make directory, name validation), `file_ops` (copy/move/trash/delete engine `run`, background `Job`; delete walks with `openat`/`unlinkat` and `O_NOFOLLOW` so a directory swapped for a symlink mid-delete can't redirect it; `Pack`/`Extract` operations in child modules: `archive_names` (formats by extension, `stem`, entry-name checks `components`, `single_top_folder`), `safe_dir` (`SafeDir`: every extraction write through `openat` + `O_NOFOLLOW`, modes `& 0o777` minus the umask; `.`/`..` parts refused), `pack` (zip via the `zip` crate; each symlink asks through `Observer::link` / `Event::Link`), `extract` (zip and tar; tar read twice: names first for smart extraction and totals); `ExtractEntries` (F5/F3 inside an archive: a `Pick` in the extract `Sink` keeps the chosen entries under `inner`, renames the top one for `Destination::As`, no smart extraction), `compare` (`Operation::Compare`, run before the engine so nothing is logged; result in `Report::comparison`: `Comparison` with `Difference`s sorted by path; walks both trees without following symlinks, then reads same-size file pairs in 1 MiB chunks); `Conflict::incoming` describes an archive entry; encrypted zip entries ask through `Observer::password` / `Event::Password` (the engine remembers the password for the job; `Decrypted` turns data errors into "wrong password or a damaged entry"; `aes_authentic` checks the authentication code of deflated AE-2 entries before extracting, since zip checks it only when the encrypted data is read to its end and AE-2 has no CRC; `PasswordAnswer`'s `Debug` hides the password)), `terminal` (Ctrl-Shift-T: `choose(&Env, dir)` picks the default terminal and its folder argument from an injected `Env` (`$TERMINAL`, KDE and its `kdeglobals`, `PATH`); `open_terminal(command, dir)` starts it in `dir` without waiting, `command` replacing the detection (app tests set `FileManager::terminal`; v2's configured emulator can use it too)), `launch` (external editor; for Enter on a file, `is_program` (any execute bit and an ELF, Mach-O or `#!` start; the bit alone isn't enough on NTFS/FAT/SMB) and `run_program` (direct, no shell, in the file's folder, exit code ignored), else `open_with` runs the system opener without waiting, and reports a non-zero exit through a callback from its own thread; output is never piped, since an app the opener starts could hold the pipe), `oplog` (operation log: day files, startup pruning; the engine writes through `file_ops::Settings::log`, F2/F7/Shift-F4 through `Commander::set_log`), `quick_search` (the typed prefix), `viewer` (F3: `source` opens regular files only, with `O_NONBLOCK` so a FIFO can't block; `layout` turns a byte window into display rows; `document` caches 64 KiB blocks and navigates by byte position; `lines` counts lines in the background, keeping a count per MiB; `search`: `find(source, query, from, Direction, cancel, progress)`, the next match forward or the last one before `from` backward, in 1 MiB blocks cut at line ends, matches by `TextQuery::find_at` (the leftmost one-line match from a position, also behind Alt-F7's `is_match_in`); `Row::marks` / `Document::marked_rows` carry the current match into the layout (two ranges per hex row), `Row::mark_columns` the first one's columns; `hex`: `Wrap::Hex` rows (`hex_row`, `offset_digits`, `HEX_ROW`), with `Document` navigating hex by arithmetic, never reading the file to find a row start; selection: `Row::sources` (the file byte of each shown character) with `boundary_at`/`char_at`/`hex_column` (`HexColumn`) for hit tests, `Highlight` (the search mark and the selection, filling `Row::marks` and `Row::selection`), `Document::word_at`/`line_at`, `copy` (`Document::copy_text`, `Copy::{Text, Hex}`, `COPY_CAP`, `TooLarge`)), `config` (`save_setting` edits one key, `save_hotlist` replaces the `[[hotlist]]` tables; both with `toml_edit`, never writing a broken file), `find` (Alt-F7: `masks` (`Masks::parse`/`new(text, case_sensitive)`/`matches`/`enters`: `;`/space separated, `*`/`?`, case-insensitive unless the dialog's Case-sensitive is checked, implied `*text*`, excludes after `|`, `name/` folders not entered), `text` (`Text::compile` to a `TextQuery` over `regex::bytes`; `is_match_in` reads 1 MiB blocks cut at line ends, a match containing `\n` is skipped, `O_NONBLOCK` open, `Interrupted` on cancel), `walk` (`search(query, cancel, progress, found)`: hands each result as an `Entry` named by its relative path; depth first in name order, hidden included, symlinks not followed; a folder on another device is skipped only if it is a mount point in `/proc/self/mountinfo` (`other_filesystem`, `parse_mountinfo`; btrfs subvolumes are searched; without the table, as on macOS, the device decides); `Progress` (atomic counts; `so_far` for the status line and a stopped search), `SearchSummary`), `Results` ("Feed to panel": root, masks text, `Arc<Vec<Entry>>` shared with the dialog, named by relative path; `listing`, `recheck` re-stats and drops gone entries), `IN_RESULTS`. A results panel keeps `Option<Arc<Results>>` beside `archive`: `path()` is the root, so `path().join(name)` is the real path; a `Navigation` carrying results is applied at once; a reload (`LoadRequest::results`) re-checks; `watch_reload` skips it; `Commander::feed`, `Commander::go_to_file` (`Navigation::up_if_missing` / `LoadRequest::up_if_missing`: only a missing folder walks up to its nearest parent, an unreadable one is an error; leaving results uses it too); quick search and icons use a name's last component; rename/mkdir/new file refuse), `hotlist` (Ctrl-D entries: `label` turns `&` marks into the letter and an underline byte range, `find_letter`, `expand`/`contract` for `~`, `validate`, `default_name`; `Commander::go_to` navigates the active panel there, `Commander::home`), `info` (Properties: `read` (a symlink's kind, size and times are its target's), `from_entry` (inside an archive), `count` (iterative walk, links never followed, `cancel` flag), `lines` (all the box's text; ## Current features

- Two panels side by side, draggable divider, resizable window; position and size, every tab's folder and the active panel restored on start (a deleted folder falls back to its nearest readable parent, then home; command-line folders override).
- Tab and Shift-Tab switch panels; Up/Down/Home/End/PageUp/PageDown move the cursor; Enter enters a directory or goes up on "..", opens an archive (zip, tar, tar.gz/bz2/xz/zst) read-only like a folder (F3 and F5 work inside; ".." at its root leaves it; it re-reads when the file changes; restart reopens its folder), and runs a program or opens any other file with the system opener (double-click too); Backspace goes up. Going up leaves the cursor on the directory you came from.
- Selection: Space toggles the entry under the cursor and moves down; Ctrl-A selects all. Ctrl-C/Ctrl-Ins (also Cmd-C on macOS) copy the full path under the cursor as text (the folder on ".."), bound in the panel context so text fields keep their own copy. Selected entries are orange (the cursor bar turns orange on a selected entry). The footer shows totals, or "N of M selected, size of total". Selection is per panel, kept by name across re-sorts, cleared on directory change. `Panel::targets()` (selection, else the cursor entry, never "..") is what file operations will act on.
- F5 copy, F6 move (wide destination prompt: one entry gets its full target path with the name preselected, so it can be renamed or sent anywhere, missing folders created; several entries get an editable target folder, with the count in the title; core `file_ops::Destination::{Into, As}`), F8/Del trash (confirm), Shift-F8/Shift-Del permanent delete (confirm), in the background with a progress dialog (after ~300 ms), Cancel, a per-file conflict prompt and an error summary; both panels reload at the end.
- F2 rename (name preselected up to the last extension; never overwrites; case-only rename allowed), F7 new directory (nested `a/b/c` allowed, nothing outside the current directory), F4 opens the entry (or the directory on "..") in `editor`; Shift-F4 asks for a file name or relative path (`a/b/c.txt`, missing folders created), creates the file (or keeps an existing one), puts the cursor on it (or its first folder) and opens it in `editor`. Alt-Z shows this directory in the other panel, Ctrl-U swaps panels, Ctrl-R reloads both. Typing opens a quick search box in the panel footer and jumps to the first name starting with the typed text; Down/Up step through matches (wrapping), Backspace shortens it, Escape or any other command closes it. The search state lives in `Commander` (`search_*`), so every command ends it.
- Mouse: click moves the cursor (and focuses that panel), double-click activates, wheel scrolls the view without moving the cursor.
- F3 views the file under the cursor in a new window (directories and ".." do nothing; FIFOs and devices show an error). Opens GB-sized files instantly. Ctrl-F searches (text, case, regex, whole words), F3 (or Enter)/Shift-F3 find the next/previous match, Escape stops a long search. `H` toggles hex mode (offset, 16 codes, ASCII). Drag (auto-scrolling), Shift-click, double-click (word) and triple-click (line) select, Ctrl-A selects all, Ctrl-C/Ctrl-Ins copy (hex: the codes or the characters, by where the drag started); a found match becomes the selection. Word wrap by default, `W` toggles no-wrap (Left/Right scroll, rows cut at 10,000 characters); Up/Down/PageUp/PageDown/Home/End (Ctrl too), mouse wheel, draggable byte-based scrollbar; status line with size, percentage, mode and "line N of M" once the background count finishes. Escape or `q` close it. Invalid UTF-8 and control characters show as a dim `·`.
- Directory names show as `[name]` when icons are off (display only; ".." unbracketed).
- Icons (default on, `icons` in the config and Settings): a Nerd Font glyph before every name, chosen by name and extension like `eza --icons`, in the row's text color; folders lose their brackets.
- Columns: Name, Size, Modified (local time), Owner (`user:group`), Permissions (`ls -l` style). Modified, Owner and Permissions can be turned off in Settings or the config (`Commander::hide_columns`, `columns::visible_columns`); a panel sorted by a hidden column goes back to Name, and the Show menu drops its sort item. Clicking a header sorts that panel by it; clicking again reverses. Size and Modified start descending. ".." then directories always come first. `case_sensitive_sort` in the config switches name comparison.
- Tabs per side: Ctrl-T copies the front tab into a new one after it, Ctrl-W closes the front tab (never the last), Ctrl-Tab/Ctrl-Shift-Tab cycle (wrapping); all on the active side, also in the Commands menu. The tab header is always shown; a click on a tab brings it and its side to the front. Background tabs keep their listing and re-read quietly when shown; only the front tab of each side is watched. A loading tab can still be left or closed. Ctrl-U swaps whole sides. Settings (hidden files, columns, icons, sort case) reach every tab.

- Panels reload on their own when their folder changes outside the app (throttled; quiet, so keys keep working; a deleted folder sends the panel to its nearest parent). Network mounts only see changes made from this machine.

- Symlinks: Owner and Permissions describe the link itself; Size and Modified come from the target.

"Add current folder" (asks for a name) and "Configure..." (OK/Cancel dialog: add, rename, change path, remove with Del, reorder with Alt-Up/Alt-Down). - Menu: Files, Commands, Show (hidden files, sort column, with check marks), Help (About); each item shows its key. macOS: the native menu bar, About and Quit in the app menu. ## Known issues and gaps

- At narrow panel widths the fixed columns (~400 px) squeeze the Name column to nothing. Hiding columns in Settings helps; resizable columns are v2.
- The owner reported that only Name sorting seemed to work on their machine; Size and Modified sort correctly in headless tests. Unverified. Note that owner/permissions sorts look like name sorts in directories where those values are all equal.
- Reading a big folder takes ~320 ms per 100k entries on Linux (~70% of it one `stat` per entry), near-instant on macOS. It runs in the background now; making the `stat` cheaper would only shorten the wait.
- A folder given on the command line is checked synchronously before the window opens, so one on a dead mount still hangs startup (accepted: the user typed it).
- No-replace rename (F2, move) is atomic only on Linux glibc (`renameat2`). On macOS it checks, then renames, so another process could create the target in between (TOCTOU); fixing it needs `renamex_np`, which nix doesn't offer without our own `unsafe`.
- A config problem shows in the status line and clears on the next keyboard command, not on mouse clicks.
- `PanelView::visible_rows` reads gpui scroll-handle internals (public fields); likely to break on a gpui upgrade.
- gpui cannot write file paths to the clipboard (copy in app, paste in Finder/Dolphin), and drag-out to other apps works on macOS and Wayland only (not X11). Both need platform code or another crate.

## Gotchas

- gpui animations run on wall-clock time (`Instant::now`), not the test clock. gpui-component's `Dialog` slides in for 250 ms, so a test that reads a control's bounds and then clicks could miss under a loaded parallel run (the settings tests failed about 1 in 25 to 60). The test `setup` turns on `cx.set_reduce_motion(true)`, which settles animations on their first frame; `dialogs_appear_in_place_so_clicks_land` guards it.
- App tests read folders inline (`open` sets `FileManager::load = None`), so keys take effect at once. To keep a panel loading, `use_held_loads` plus a `hold` file in the folder being read; drive it with `wait_until`. Core tests finish reads with `run_loads_now` (or the `run` helper).
- App tests have no real watchers (`FileManager::new` starts none under `cfg(test)`: a report from a watcher thread would panic gpui's test scheduler); report a change with `changed(cx, side)` or any `watch::Report` with `report(cx, ...)`. Core watcher tests use real time and notify; `watch_and_wait` returns once the watch is in place.
- Tests must never call the real `trash::delete` (it would fill the owner's trash): core `file_ops` tests pass `file_ops::Settings { trash: fake_trash, .. }` to `run` / `Job::spawn`, and app tests set `FileManager::trash` to a fake (`use_fake_trash`). Only `scripts/smoke.sh` uses the real trash, with `XDG_DATA_HOME` in a temporary folder.
- A panel's `path()` can run through an archive file (`/x/a.zip/src`): use `real_dir()` for anything on disk (watcher, state file, hotlist). Writing commands call `FileManager::refuse_in_archive`; core `rename`/`make_directory`/`create_file` refuse too, and a stray `path().join(name)` inside an archive can't exist, so it fails instead of touching the real folder. F3 inside an archive runs a `Kind::View` job (not logged); the viewer window owns the `tempfile::TempDir`, under `viewer-tmp/<pid>` (`storage::clear_stale_temp` at startup removes folders of instances no longer running; app tests set `FileManager::temp_dir`, `None` by default).
- Ctrl-Shift-T in tests: `window_on` sets `FileManager::terminal` to `true`, so no real terminal starts; `mod open_terminal` uses `sh -c 'pwd > out'`. The smoke script exports `TERMINAL` as a recording script, which goes through the real detection.
- Enter on a file: `FileManager::open_file` decides and starts on a `std::thread` (reading the file's header could hang on a dead mount). `FileManager::opener` is the program run for non-programs (`xdg-open`/`open`); app tests set it to `true` in `window_on` so no real app ever starts, and `mod open_file` tests use a recording script. A failure comes back over a std channel polled every 100 ms (`OPENER_POLL`): a futures wake-up from the opener's thread panics gpui's test scheduler ("not deterministic"). Tests that exec a freshly written script first run it until it no longer fails with ETXTBSY (another test's fork can briefly hold it open for writing). The smoke script puts a recording `xdg-open` first on `PATH` and runs an executable `run.sh`.
- App tests of F5/F6 run a real worker thread: drive them with `advance_clock` + `run_until_parked` in a loop (`wait_until` in `file_manager/tests.rs`); the poll timer only fires on the test clock.

- gpui-component `Dialog` maps Enter to its OK action (`on_ok`) for the whole dialog, even when a text input or another button has focus (upstream bug, not reported as of 2026-09-30), and has no arrow-key navigation. So every dialog's buttons are our `ButtonRow` (`button_row.rs`), never `DialogFooter`/`DialogAction`/`open_alert_dialog`: it keeps its own selected button and binds Left/Right, Tab/Shift-Tab, Enter and Space in its own key context. Focus the row when a dialog opens (`focus_when_open`), except prompts, which focus their text field (Enter there still goes to `on_ok`; don't also handle the input's `PressEnter`, or OK runs twice: `enter_submits_a_prompt_exactly_once`).
- A gpui-component `Dialog` body (`.child`) clips its children and has no vertical padding, and the focus ring is drawn 3 px outside a control. A text field at the top or bottom of a body goes through `dialog_field` (`file_manager/commands.rs`), which adds the room; otherwise the ring is cut off top and bottom.
- gpui's Linux text system drops any font without a glyph for `m` (gpui-pre-wgpu `cosmic_text_system.rs`, `load_family`), silently, so text falls back to the UI font and shows hex boxes. The bundled symbols font is patched to map `m` to an empty glyph (`scripts/patch-icon-font.py`, needs fontTools); the core test `the_font_maps_m_so_gpui_keeps_it` guards it. App tests use a no-op text system, so only a screenshot shows whether glyphs render.
- A popup drawn inside a dialog (`deferred(anchored(...))`) needs `.with_priority(gpui_kit::base::POPUP_PRIORITY)`: the dialog layer itself is deferred with priority 10 and up, so a lower one paints underneath it and is invisible. App tests can't see this (the popup is laid out and even takes clicks there); only a screenshot does (`08i1-find-skip-popup` in the smoke run).
- Opening a dialog moves focus to it: focus a field inside it with `window.defer` after opening. After an error box closes, focus must be put back explicitly (`show_error`'s `refocus`).
- An event handler running inside an entity's update must not update that same entity again (panics "already being updated"); defer with `window.defer`.
- Tests of the settings dialog: point `CurrentConfig.path` (helper `use_config`) and `FileManager::log_dir` (`use_log_dir`) at temporary folders, never the real ones. Call `activate(cx)` first (blur events need an active window), and use `press(cx, key)` for Space/Enter on a switch or button (gpui clicks on key-up; `simulate_keystrokes` sends only key-down).
- Text fields: use `commands::text_field`, never a bare `Input::new`. gpui-component's default input (32 px, 8 px vertical padding) leaves 14 px for a 20 px line and cuts off descenders; `text_field` sets 5 px.
- `ThemeConfigColors` (gpui-component) has private fields: build it from `default()` and assign fields, not with struct-update syntax.
- Viewer windows in app tests: find them with `viewer_view::tests::viewer_in` over `cx.windows()` and drive them with `VisualTestContext::from_window`. In the smoke script (no window manager) the new viewer window must be focused with `xdotool windowfocus`.
- Menu shortcut labels: gpui-component's menus (Linux) show an action's last-registered binding, the native macOS menu its first (gpui-pre-macos `platform.rs`). So a primary key is registered both before and after its alternative (F8, Del, F8). Quit has one binding per platform for the same reason. Pinned by `menu_labels_show_the_primary_keys`.
- gpui dispatches key bindings before `on_key_down` listeners. The hotlist popup's `on_key_down` stops letters from reaching the quick search, but a file-manager binding on a bare (or Shift) character would still fire while the popup is open, since `hotlist_popup::passes` lets single characters through. Keep such bindings out of the `FileManager` context, or extend `passes`.
- Lone Alt is gpui's modifier-only binding `"alt"` (fires on release if no key came in between). gpui doesn't count mouse clicks or window switches, so `FileManager::alt_armed` is cleared by those. A keystroke interceptor (`intercept_keystrokes` in `FileManager::new`) swallows every key but the menu's own while a menu is open, because the panel bindings are on the open popup's dispatch path. gpui test windows start inactive, and gpui reports focus changes (`on_focus_out`) only for the active window: call `window.activate_window()` first in such tests. An open menu closes when focus leaves its popup (e.g. a dialog opens). Lone-Alt tests that follow an activation advance the test clock past `ALT_AFTER_ACTIVATION`. The menu-bar app tests are in `mod menu_bar` in `file_manager/tests.rs`, compiled on Linux only.
- Icons (e.g. menu check marks) need gpui-kit's assets: `main.rs` registers `gpui_kit::assets::Assets`; without it icons render blank.
- Alt-F4 is bound to Quit (Linux); the `Viewer` context rebinds it to close only that viewer.
- Archive tests build malicious archives on purpose: `zip::ZipWriter::start_file` accepts any name; tar names and link names go in raw through `header.as_old_mut()` (`set_path` refuses `..`). `ZipFile::unix_mode()` includes the file-type bits. `tar::Header::mode()` fails on headers without a mode.
- Encrypted zip tests: ZipCrypto and AES headers start with random bytes, so a wrong password passes the quick check by chance (ZipCrypto 1 in 256). Tests that need a wrong password rejected rewrite the zip until it is (`make_locked_zip`'s `rejects`).
- macOS (unverified): apps started from Finder get a minimal `PATH`, so an `editor` like `code` may not be found; use a full path in the config if so.

## Building

- Rust via rustup (latest stable).
- macOS: Xcode. gpui-kit enables gpui's `runtime_shaders` and `font-kit` features, so Metal shaders compile at runtime and the full Xcode app may no longer be required (unverified; if the build asks for `metal`, install Xcode and `sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer`).
- Kubuntu: `sudo apt install build-essential pkg-config clang cmake libxkbcommon-dev libxkbcommon-x11-dev libwayland-dev libfontconfig-dev libfreetype-dev libx11-dev libx11-xcb-dev libxcb1-dev libvulkan-dev`
- Arch/Omarchy: `sudo pacman -S --needed base-devel clang cmake libxkbcommon libxkbcommon-x11 wayland fontconfig freetype2 libx11 libxcb vulkan-icd-loader` plus the Vulkan driver for your GPU.
- For `scripts/smoke.sh` (Linux only; package names not yet verified on the owner's machines): Kubuntu `sudo apt install xvfb xdotool x11-utils imagemagick xclip mesa-vulkan-drivers`; Arch `sudo pacman -S xorg-server-xvfb xdotool xorg-xprop imagemagick xclip vulkan-swrast`.

### Fresh dev container (Ubuntu 24.04, no display)

Containers are ephemeral; redo this at the start of a session if `~/.cargo/bin/cargo` is missing.

```sh
curl -sSf https://sh.rustup.rs | sh -s -- -y --profile minimal -c clippy,rustfmt
sudo apt-get install -y build-essential pkg-config clang cmake libxkbcommon-dev libxkbcommon-x11-dev \
  libwayland-dev libfontconfig-dev libfreetype-dev libx11-dev libx11-xcb-dev libxcb1-dev libvulkan-dev \
```

Cargo is at `~/.cargo/bin/cargo` (not on PATH in non-login shells). A clean build takes a few minutes.

## Commands

- `cargo run --release -- [left-dir] [right-dir]`: run the app (the default workspace member). Without arguments it reopens the folders from the last run.
- `cargo test --workspace` and `cargo clippy --workspace --all-targets` (must be warning-free).
- `cargo llvm-cov --workspace --summary-only`: coverage. Core is kept near 100%; the uncovered lines need root or a file owned by an unknown uid.
- App tests live in `file_manager/tests.rs`. Mouse tests find elements by `debug_selector` (`row-left-3`, `tab-left-0`, `header-right-Size`, `divider`, `search-left`) and `cx.debug_bounds`; a missing selector also means the element was not drawn. Jobs that must stay running use `use_fake_trash` plus a `hold` file.
- App tests use gpui's `TestAppContext` (`#[gpui_kit::test]`) and build the window like the app does (`gpui_kit::init` + `Root`), so dialogs work. Drive them with `simulate_keystrokes` / `simulate_input` and `run_until_parked`; check dialogs with `window.has_active_dialog(cx)`. gpui's test window does not expose the title, so title text lives in a pure function.
- `scripts/smoke.sh [screenshot-dir]`: runs the real debug build under Xvfb through the main features (Enter on a file via a fake `xdg-open`, quick search, Ctrl-C/Ctrl-Ins path copy checked with xclip, F7, Shift-F4, F2, F5 with a conflict, F6, F8 into a temporary trash, Shift-Del, Ctrl-., Ctrl-D (add the folder to the hotlist, jump back by its letter, checked by window title), the Owner column switch (hidden through the restart), Files > Compare by content on two folders through F10 (checked with xclip), Alt-F7 (a name search with an exclude fed to the panel and copied out with F5, a content search with go to file checked by window title), F3 on a 200,000-line file (a mouse drag copied with Ctrl-C, checked with xclip) and a 300 KB single line, a file created and a folder deleted outside the app (watcher), tabs (Ctrl-T, Ctrl-Tab, Ctrl-Shift-Tab, Ctrl-W, a background tab catching up), quit, restart without arguments onto the saved tabs), checks the results on disk (including the operation log and its startup pruning) and saves screenshots to `target/smoke/`. Config, state and trash are in a temporary folder. Linux only; needs Xvfb, xdotool, ImageMagick, xclip.
- `scripts/make-test-files.sh [count] [dir]`: create a large directory under `/tmp` for stress tests.
- `RUST_LOG=info` shows gpui's platform logs (renderer, fonts, windowing).

### Headless run (to see the real app in the container)

Xvfb gives a virtual X11 display, Mesa's llvmpipe renders Vulkan on the CPU, xdotool sends input, ImageMagick screenshots. Scratch `XDG_*` dirs keep config/state away from real files.

```sh
S=<scratchpad>; mkdir -p $S/xdg $S/cfg $S/state; chmod 700 $S/xdg
export DISPLAY=:99 XDG_RUNTIME_DIR=$S/xdg XDG_CONFIG_HOME=$S/cfg XDG_STATE_HOME=$S/state
(Xvfb :99 -screen 0 1280x860x24 >/dev/null 2>&1 &); sleep 1
(target/debug/yagni-commander /usr /etc >$S/app.log 2>&1 &); sleep 4
W=$(xdotool search --name yagni-commander | head -1); xdotool windowfocus $W; sleep 0.5
xdotool key Down F2; xdotool type --delay 40 "name"; xdotool key Return
import -window root $S/shot.png        # then read the PNG
xdotool key alt+F4; pkill -x Xvfb
```

- Pause (`sleep 0.3`+) after focusing, moving or resizing before sending keys; gpui also ignores a click sent in the same instant as the pointer move.
- Never `pkill -f` a pattern that matches your own shell command line; use `pkill -x yagni-commander`.
- X11 only, no window manager: Wayland, tiling (Hyprland) and macOS are untested here.
